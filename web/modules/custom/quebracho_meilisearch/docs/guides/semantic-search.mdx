title: Semantic and hybrid search
---

1. Configure an embedder on the Meilisearch index (Cloud dashboard or [settings API](https://www.meilisearch.com/docs/reference/api/settings#embedders)). The index name is the index prefix followed by the Search API index machine name.
2. On the server, set **Search mode** to *Hybrid* or *Semantic* and enter the embedder name.

*Hybrid* mixes keyword and semantic results according to the **Semantic ratio** (0 is keyword only, 1 semantic only). *Semantic* uses a ratio of 1.

## Vectors computed by Drupal

When another module already computes embeddings (an AI provider, a vector table), Meilisearch can store them instead of calling a model itself:

1. On the server, enter the **Embedder** name and the number of dimensions under **Vectors provided by Drupal**. The module declares a `userProvided` embedder on its indexes and re-indexes. It owns that name: an embedder of the same name already on the index is replaced, and changing the name, or setting 0, removes it. Declaring a new embedder empties the indexes before they are indexed again, as Meilisearch refuses one that existing documents have no vectors for. New dimensions for the same embedder keep the documents and their old vectors: until they are indexed again, searches that send a vector fail with `invalid_vector_dimensions`.
2. Implement [`hook_meilisearch_documents_alter()`](/reference/hooks#hook_meilisearch_documents_alter) to add each document's vector under `_vectors`.

A `userProvided` embedder cannot embed search keys: on a *Hybrid* server, searches without a vector of their own find keyword matches only, and *Semantic* search is refused.

Each document carries its whole vector: with 4,096 dimensions, a batch of 50 items is about 4 MB of JSON. Keep the index's batch size within Meilisearch's payload limit (`http_payload_size_limit`, 100 MB by default; proxies and Meilisearch Cloud may allow less).

## Searching by vector

A query can bring its own vector, embedded by the caller with the embedder's model:

```php
$query->setOption('quebracho_meilisearch_vector', $vector);
```

It is searched with the server's embedder: mixed with the keys by the semantic ratio on a *Hybrid* server, by vector alone otherwise (the keys are then ignored). Facet counts use the same vector. With vectors provided by Drupal, the vector must have the declared dimensions.

A query that uses the embedder (with a vector, or on a hybrid or semantic server) can also set its own semantic ratio, from 0 (keywords only) to 1 (vector only):

```php
$query->setOption('quebracho_meilisearch_vector', $vector);
$query->setOption('quebracho_meilisearch_semantic_ratio', 0.3);
```

With vectors provided by Drupal, Meilisearch cannot embed the keys: a query with keys and a ratio of 1 needs a vector, or Meilisearch refuses it.

## More like this

With an embedder set, the server supports Search API's "More like this" (the *More like this* contextual filter in Views): results are Meilisearch's [similar documents](https://www.meilisearch.com/docs/reference/api/similar) for the item given, by that embedder's vectors.

- The argument can be an entity ID, as Views passes it, or a Search API item ID. Of an entity's translations, the first one indexed in the query's languages is the reference, and none of them is a result. Each translation tried costs a request: the entity's own language first keeps that to one.
- An index with several entity datasources finds an entity ID in each; a `datasource` key in the `search_api_mlt` option (for example `entity:node`) restricts it to one.
- Conditions, languages and location apply; keys, sorts, facets and the filter's field list do not. Counts are Meilisearch's estimate, except on a short page, the last one, where they are exact. A query without a limit asks for up to the server's maximum number of results; Views always sets one.
- Scores are Meilisearch's ranking scores of vector similarity (0 to 1), not keyword relevance.
- An item without a vector has no similar documents, and is not similar to any.
- Access to the reference is not checked, as with other backends; results are, like any search. To hide what is similar to an item a visitor cannot see, validate the contextual filter in Views (*Specify validation criteria*: the entity type, with an access check).

## What each feature needs

| Feature | Embedder name | Vectors provided by Drupal | Query vector |
|---|---|---|---|
| Hybrid or semantic search, embedder managed in Meilisearch | yes | 0 | no |
| Hybrid search, vectors provided by Drupal | yes | dimensions | yes, for the semantic part |
| Search by vector (`quebracho_meilisearch_vector`) | yes | either | yes |
| More like this | yes | either | no |
