---
title: Search behavior
description: How Search API queries map to Meilisearch, and where results differ from the Database backend.
---

## Keywords

- Meilisearch has no boolean operators. Parsed keys are flattened into words; the server's **matching strategy** decides how many must match.
- Multi-word keys (quoted phrases) stay phrases. Negated keys become negative keywords (`-word`), each word negated on its own.
- The last word matches as a prefix (`foo` finds `foobar`) and typos are tolerated.

## Conditions

- Every Search API operator is supported, on every indexed field and on `search_api_id`, `search_api_datasource` and `search_api_language`.
- String conditions are case-insensitive.
- Conditions on fulltext fields match the whole field value, not words in it.
- Exact conditions on string values longer than about 250 bytes cannot match: Meilisearch truncates long filter values.
- Conditions that cannot be expressed raise an exception instead of being ignored.

## Sorting

- Sorts are strict on indexes created by this module. On indexes created elsewhere, whether they are strict depends on where the `sort` ranking rule sits.
- *Relevance* is Meilisearch's order. When relevance comes first and the search has keywords, later sorts are ignored.
- Random sorting is not supported.

## Vectors

- A `quebracho_meilisearch_vector` query option searches by that vector with the server's embedder; without an embedder, or with a vector that is not a list of finite numbers (of the declared dimensions, for vectors provided by Drupal), the query throws.
- On a keyword or semantic server, a vector is searched alone and the keys are ignored, unless the query sets `quebracho_meilisearch_semantic_ratio` (0 to 1).

## More like this

- Needs an embedder on the server, and uses Meilisearch's similar documents: keys, sorts and facets are ignored, and counts are Meilisearch's estimate, exact on the last page. See [Semantic and hybrid search](/guides/semantic-search#more-like-this).

## Results

- Result counts are exact when the offset is a multiple of the page size (always the case with Views pagers), estimated otherwise.
- Each result carries its Meilisearch ranking score (0 to 1), and the result set its processing time (`quebracho_meilisearch_processing_time_ms` extra data).
- A failed search is never cached: Views shows no results until Meilisearch answers again.
