title: Server configuration

| Setting | Description |
|---|---|
| Meilisearch URL | Full URL including the port, for example `http://127.0.0.1:7700` or `https://ms-abc123.fra.meilisearch.io`. |
| API key | See below. Leave empty when editing to keep the stored key. |
| Index prefix | Prepended to Meilisearch index names (`prod_`, `staging_`) so several sites or environments can share an instance. Changing it requires re-indexing. |
| Search mode | Keyword, hybrid or semantic. See [Semantic search](/guides/semantic-search). |
| Embedder | The embedder of semantic and hybrid search, and of the vectors Drupal provides. |
| Vectors provided by Drupal | 0, or the dimensions of a `userProvided` embedder the module declares and modules fill. See [Vectors computed by Drupal](/guides/semantic-search#vectors-computed-by-drupal). |
| Matching strategy | How many query words must match: `last` (Meilisearch default), `all` or `frequency`. |
| Maximum number of results | How many results a search can page through (`pagination.maxTotalHits`). Default 10,000. |

## API key

Create a dedicated key with these actions: `search`, `documents.*`, `indexes.*`, `settings.*`, `tasks.get`, `version`. Avoid the master key.

To keep the key out of configuration exports, set it in `settings.php`:

```php
$config['search_api.server.SERVER_ID']['backend_config']['api_key'] = getenv('MEILISEARCH_API_KEY');
```

The same works for the URL, so each environment points at its own instance.

## Changing the connection

Saving the server with a new URL, key or index prefix creates the indexes on the new target, pushes their settings and queues everything for re-indexing. When the URL comes from a `settings.php` override instead, the module creates a missing index the first time it indexes into it.

Read-only indexes are never created and their settings never changed: use them to search an index another site or environment maintains.

## What the module manages

On every index save the module sends the searchable, filterable and sortable attributes, `pagination.maxTotalHits`, and faceting settings (1,000 values per facet, ranked by count). When it creates an index it also puts the `sort` ranking rule first, so explicit sorts are strict. It never touches synonyms, stop words, typo tolerance or embedders, nor the ranking rules of existing indexes; the one exception is the embedder of vectors provided by Drupal, which it declares and removes.

## Discouraged processors

Meilisearch tokenizes and normalizes text itself. The Search API processors *Ignore case*, *Stemmer*, *Stopwords*, *Tokenizer* and *Transliteration* would alter what it receives; Search API warns when they are enabled.
