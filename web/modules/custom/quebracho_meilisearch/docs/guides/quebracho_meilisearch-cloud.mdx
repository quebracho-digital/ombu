title: Meilisearch Cloud
description: Connect your Drupal site to a Meilisearch Cloud project.
---

You need a Meilisearch Cloud project and the module [installed](/installation). The rest happens in the Cloud dashboard and Drupal's admin pages.

<Steps>
  <Step title="Create a project">
    Sign in to [Meilisearch Cloud](https://cloud.meilisearch.com) and create a project. Pick the region closest to your Drupal hosting: every search is a request from your server to the project.
  </Step>
  <Step title="Copy the project URL">
    The project overview shows its **Project URL**, for example `https://ms-1a2b3c4d5e6f-1234.fra.meilisearch.io`. Copy it as is: Cloud URLs have no port.
  </Step>
  <Step title="Get an API key">
    Open the project's **Settings → API Keys**. To try the module, copy the **Default Admin API Key**. For production, create a dedicated key: see [A dedicated key](#a-dedicated-key).

    <Warning>The **Default Search API Key** does not work here: it cannot create indexes or add documents.</Warning>
  </Step>
  <Step title="Add the server in Drupal">
    Go to **Configuration → Search and metadata → Search API → Add server** (`/admin/config/search/search-api/add-server`):

    - **Server name**: for example `Meilisearch`.
    - **Backend**: **Meilisearch**.
    - **Meilisearch URL**: the project URL.
    - **API key**: the key from the previous step.
    - **Index prefix**: optional, see [Several environments on one project](#several-environments-on-one-project).

    Save. If Drupal cannot reach the project or the key is refused, a warning says why: see [Troubleshooting](#troubleshooting).
  </Step>
  <Step title="Check the connection">
    The server page shows:

    | Row | Expected value |
    |---|---|
    | Meilisearch Cloud | Yes |
    | Connection | Connected |
    | Meilisearch version | The version of your project |

    Once you add indexes, it also lists each one with its number of documents. Continue with the [Quickstart](/quickstart) from **Add an index**.
  </Step>
</Steps>

## Keep the key out of configuration

Configuration exports (`drush config:export`) contain the server settings, API key included. Set the key, and the URL if you like, in `settings.php` from environment variables instead:

```php
$config['search_api.server.meilisearch']['backend_config']['url'] = getenv('MEILISEARCH_URL');
$config['search_api.server.meilisearch']['backend_config']['api_key'] = getenv('MEILISEARCH_API_KEY');
```

Replace `meilisearch` with your server's machine name. The server form then shows these settings read-only, marked *Set in settings.php*, and the server page lists them under **Set in settings.php**.

## A dedicated key

The Default Admin API Key can do anything except manage keys. In production, give Drupal a key limited to what the module needs: `search`, `documents.*`, `indexes.*`, `settings.*`, `tasks.get` and `version`.

Create it with the Meilisearch API, authenticated with your project's master key:

```bash
curl -X POST 'https://ms-1a2b3c4d5e6f-1234.fra.meilisearch.io/keys' \
  -H 'Authorization: Bearer MASTER_KEY' \
  -H 'Content-Type: application/json' \
  --data-binary '{
    "description": "Drupal",
    "actions": ["search", "documents.*", "indexes.*", "settings.*", "tasks.get", "version"],
    "indexes": ["*"],
    "expiresAt": null
  }'
```

The `key` field of the response is the API key for Drupal. With an index prefix you can limit the key to it, for example `"indexes": ["prod_*"]`.

## Several environments on one project

Production, staging and developer machines can share one Cloud project. Give each Drupal server its own **Index prefix**, such as `prod_`, `staging_` or `dev_alice_`, so their indexes never collide. Set it per environment in `settings.php`:

```php
$config['search_api.server.meilisearch']['backend_config']['index_prefix'] = getenv('MEILISEARCH_INDEX_PREFIX');
```

To let an environment search production's data without writing to it, use production's prefix and tick **Read-only** on its Search API index.

## Relevancy settings

The module manages which attributes are searchable, filterable and sortable. Synonyms, stop words, typo tolerance, ranking rules and embedders stay in Meilisearch: edit them in the Cloud dashboard, which the server edit form links to.

Cloud also enables [click analytics](/guides/analytics) and [semantic search](/guides/semantic-search).

## Troubleshooting

| Symptom | Fix |
|---|---|
| *Could not connect to Meilisearch* with a timeout or DNS error | Copy the project URL exactly, without `:7700` or a trailing path. Check that your hosting allows outgoing HTTPS requests. |
| *The provided API key is invalid* | The key was mistyped, deleted or has expired. Copy it again from **Settings → API Keys**. |
| Indexing fails with a permission error | The key lacks an action, often because it is the Default Search API Key. Use a key with the actions in [A dedicated key](#a-dedicated-key). |
| The URL or key field is greyed out | It is set in `settings.php`: change it there. |
| The server page shows *not created yet* for an index | Click **Start indexing now** on the index: the module creates missing indexes when it indexes. |
